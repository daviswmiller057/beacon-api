# Beacon CLI implementation report

## 1. Summary

Beacon now has a minimal, dependency-free terminal client launched with
`python -m app.cli`. It supports an interactive REPL, natural-language one-shot
requests, direct brief/status/health commands, environment and command-line
configuration, human-readable output, optional raw JSON debug output, and
friendly errors for common connection and API failures.

The CLI is only an HTTP client. It sends ordinary input unchanged to
`POST /interact`; it does not import or invoke Beacon's interpreter, planner,
executor, scheduler, or integration services. All intelligence and side effects
remain in the Beacon backend.

Architectural review:

1. The CLI contains no business logic; it only selects documented endpoints and
   formats their responses.
2. Intake, planning, execution, scheduling, and integration behavior remain
   inside Beacon.
3. A future web UI can use the same `/interact`, `/brief`, `/status`, and
   `/health` API.
4. A future voice interface can use the same API without depending on this CLI.
5. The CLI is replaceable without any backend change.

## 2. Files changed

- `app/cli/__init__.py` — configuration, HTTP client, response formatting, REPL,
  argument parsing, and one-shot execution.
- `app/cli/__main__.py` — `python -m app.cli` entry point.
- `tests/test_cli.py` — mocked unit and command-mode coverage.
- `CLI_USAGE.md` — setup, configuration, commands, examples, debug usage, and
  troubleshooting.
- `README.md` — link and quick launch note for the CLI.
- `CLI_IMPLEMENTATION_REPORT.md` — this report.

No dependencies were added. The implementation uses Python's standard-library
`urllib` transport.

## 3. How to run the CLI

From the repository root:

```bash
export BEACON_API_URL=http://localhost:8000
export BEACON_API_KEY='replace-with-your-key'
python -m app.cli
```

One-shot examples:

```bash
python -m app.cli "Buy Liquid IV tomorrow"
python -m app.cli --brief
python -m app.cli --status
python -m app.cli --health
```

Use `python -m app.cli --help` for all client options and `--debug` for complete
JSON responses and error tracebacks. See `CLI_USAGE.md` for full instructions.

## 5. Tests added and results

`tests/test_cli.py` adds 17 mocked tests covering:

- environment loading, defaults, command-line overrides, URL validation, and
  missing-key handling;
- JSON request construction and `X-Beacon-API-Key` authentication;
- `/interact`, `/brief`, `/status`, and public `/health` requests;
- invalid credentials, offline service, timeout/network failure, server errors,
  and malformed JSON;
- natural-language and brief one-shot operation;
- interactive help, commands, ordinary input, clean exit, and recoverable
  per-request errors.

Results in the supplied workspace:

```text
tests/test_cli.py: 17 passed in 0.15s
broad non-TestClient run: 75 passed, 4 deselected in 0.60s
compileall: passed
git diff --check: passed
```

The complete suite was attempted before and after the change. In this workspace
it stalls in pre-existing FastAPI `TestClient` endpoint tests; even
`tests/test_health.py` alone times out. A faulthandler stack trace shows the wait
inside the AnyIO/Starlette blocking portal under Python 3.14.6. The repository's
documented runtime is Python 3.12. All 75 tests that avoid that portal pass; the
four other endpoint tests were deliberately deselected in the broad completed
run, and the standalone health endpoint test demonstrates the same environment
stall. No CLI test uses a live service or FastAPI `TestClient`.

## 6. Known limitations

- The CLI expects JSON responses matching the current documented API contract.
- It does not store configuration or credentials; each shell/session must supply
  the environment variables or options.
- Interactive input has no persistent history, completion, colors, or rich
  terminal rendering.
- Brief one-shot mode currently requests today's brief and does not expose the
  API's optional date query parameter.
- Debug mode prints response JSON, but there is no separate machine-stable output
  mode intended for scripts.
- Full-suite verification should be repeated in the supported Python 3.12
  environment because of the Python 3.14 `TestClient` deadlock described above.

## 7. Recommended next improvement

Add an optional `--date YYYY-MM-DD` companion to `--brief`. This would expose the
backend's existing read-only query parameter for shell and mobile shortcuts
without adding interpretation or business logic to the CLI.
