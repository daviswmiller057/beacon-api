## Effective API contract

- HTTP method: `GET`
- Effective public endpoint: `/api/v1/dashboard/today`
- Authentication header: `X-Beacon-API-Key: <configured key>`
- Authentication environment variable: `BEACON_API_KEY`
- Content type: JSON with snake_case field names.

Exact top-level fields:

- `schema_version`: integer literal `1`
- `generated_at`: timezone-aware RFC 3339/ISO-8601 timestamp
- `timezone`: configured IANA timezone name
- `local_date`: ISO calendar date in that timezone
- `display_name`: nullable string
- `next_event`: nullable event summary
- `focus`: nullable task summary
- `attention_items`: array of attention items
- `priority_tasks`: array of task summaries
- `recommended_action`: nullable recommended-action summary

Nested event-summary fields:

- `id`: string
- `title`: string
- `start_at`: timezone-aware timestamp
- `end_at`: timezone-aware timestamp, strictly after `start_at`
- `location`: nullable string
- `leave_by_at`: nullable timezone-aware timestamp
- `calendar_name`: nullable string

Nested task-summary fields:

- `id`: string
- `title`: string
- `project_name`: nullable string
- `priority`: `none`, `low`, `medium`, `high`, `urgent`, or `do_now`
- `due_at`: nullable timezone-aware timestamp
- `completed`: boolean

Nested attention-item fields:

- `id`: string
- `title`: string
- `detail`: nullable string
- `severity`: `info`, `warning`, or `critical`
- `source`: `task` or `calendar`

Nested recommended-action fields:

- `title`: string
- `detail`: nullable string
- `kind`: `review`
- `related_id`: nullable string

Null and empty-array semantics:

- `display_name` is null because Beacon has no deterministic display-name
  source.
- `next_event` is null when the existing calendar snapshot has no current or
  next ordinary event, or calendar data is unavailable.
- `focus` is null because Beacon has no supported deterministic focus-selection
  behavior.
- `attention_items` is empty when there are no real overdue tasks or supported
  attention concepts available.
- `priority_tasks` is empty when no qualifying incomplete tasks are exposed by
  the existing Daily Brief task groups or task data is unavailable.
- `recommended_action` is null because Beacon has no supported deterministic
  recommendation behavior.
- Unsupported intelligence is omitted rather than fabricated.

## Architecture

Route layer:

- `app/main.py` mounts `app.api.dashboard` at `/api/v1/dashboard`.
- The router defines only `/today`, producing the exact effective path
  `GET /api/v1/dashboard/today` without duplicating the prefix.
- The route authenticates through a router dependency, resolves an injectable
  `TodayDashboardService`, invokes `build()`, and returns the explicit
  `TodayDashboardResponse` model.
- The route imports and invokes no Vikunja, CalDAV, Nextcloud, Waze, Home
  Assistant, Gemini, n8n, HTTP, scheduling, or mutation client.

Dashboard assembly service:

- `TodayDashboardService` is a read-only projection over the existing
  `DailyBriefService` response.
- It maps provider IDs to stable strings, normalizes boundary datetimes to the
  configured timezone, limits qualifying priority tasks to five, maps existing
  overdue tasks to attention items, and leaves unsupported sections null.
- It adds no scheduling, rescheduling, conflict-severity, focus, recommendation,
  or model-generated policy.

Existing task and calendar service usage:

- `DailyBriefService` calls the existing `VikunjaClient.list_tasks()` read
  interface and `CalDAVService.fetch_calendar_events()` read interface.
- The dashboard service consumes the already-normalized Daily Brief output. It
  does not call provider adapters itself.
- `project_name` remains null because the normalized Vikunja task model exposes
  a numeric project ID but no project-name lookup.

Clock and timezone handling:

- `DailyBriefService` already accepts an injectable clock with signature
  `Callable[[ZoneInfo], datetime]`.
- It loads configured `BEACON_TIMEZONE`, obtains `generated_at` from that clock,
  derives the local date in that timezone, and uses timezone-aware day bounds.
- The dashboard maps generated, event, due, and leave-by timestamps into the
  same configured timezone. Its response models reject naive timestamps, and
  the event model rejects end times that do not follow start times.

Authentication boundary:

- The endpoint reuses `require_api_key` from `app/security.py`.
- That dependency reads `X-Beacon-API-Key`, compares it to required setting
  `BEACON_API_KEY` with timing-safe `hmac.compare_digest`, and returns the same
  401 detail for missing and invalid values.
- No parallel iOS-specific token or broader authentication system was added.

Error behavior:

- Existing Daily Brief behavior preserves partial results when calendar or
  task reads fail; provider exception details remain inside its warnings and
  are not projected into the dashboard response.
- An unexpected dashboard assembly failure returns generic HTTP 502 detail
  `Today dashboard generation failed` without exposing a raw exception or
  provider payload.
- The route does not broadly convert failures into fabricated success data.

## Data-source behavior

### next_event

- Real source: `DailyBriefService.summary.next_event`, built from
  `CalDAVService.fetch_calendar_events()`.
- Existing deterministic rule: exclude Beacon work blocks; for today's
  snapshot select the first ordinary event whose end is after `generated_at`,
  allowing an event already in progress. Return null when none exists.
- The event's CalDAV UID becomes its string ID. When the normalized event has no
  UID, the dashboard uses a deterministic SHA-256 identifier derived from
  calendar, title, start, and end.
- `leave_by_at` is populated only when the existing enabled Daily Brief travel
  behavior produced a matching estimate; otherwise it is null.

### focus

- Current value: null.
- Reason: the backend has deterministic highest-priority task selection, but no
  distinct supported focus-selection behavior. The implementation does not
  equate the first task with focus.

### attention_items

- Real source: `DailyBriefService.tasks.overdue`.
- Existing deterministic rule: incomplete tasks with a due date before the
  configured local date become warning-severity task attention items.
- The array is empty when no overdue tasks exist or task data is unavailable.
- Existing calendar conflicts are not mapped because no established dashboard
  severity policy exists for them.

### priority_tasks

- Real source: the existing Daily Brief highest-priority, overdue, and due-today
  task groups, all ultimately supplied by `VikunjaClient.list_tasks()`.
- Existing deterministic rule: highest priority uses provider priority
  descending, due timestamp ascending with missing due dates last, and numeric
  task ID ascending. The dashboard places that task first, then remaining
  overdue tasks and due-today tasks in their existing order, removes
  duplicates, excludes completed tasks, and limits the response to five.
- Numeric task IDs are serialized as strings. Integer priority maps to the
  documented boundary enum: nonpositive to `none`, 1 to `low`, 2 to `medium`,
  3 to `high`, 4 to `urgent`, and 5 or greater to `do_now`.

### recommended_action

- Current value: null.
- Reason: no existing deterministic recommendation behavior supplies a native
  dashboard action. No heuristic or model-generated action is fabricated.

## Assumptions

- The established shared `BEACON_API_KEY` remains the authoritative auth
  mechanism because it already protects every non-health application endpoint.
- The `/api/v1` segment is explicitly part of this router mount because the
  application has no global `/api/v1` prefix.
- Vikunja integer priority values retain their existing provider semantics when
  translated into the documented API enum; the translation does not alter task
  ranking.
- A deterministic content hash is the only available stable fallback for the
  rare normalized calendar event without a UID.
- Reusing Daily Brief's existing partial-degradation behavior is preferable to
  failing the whole dashboard when one read source is unavailable.
