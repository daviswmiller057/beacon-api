Beacon LLM Conversation Runtime Bug Fix Report

Completion status
Complete for the reported runtime defect.

Root cause
The conversation dependency factory in app/api/conversation.py constructed the
settings, database, Gemini provider, repository inputs, and deterministic
InteractionService, but it never returned a ConversationService. The intended
return statement was incorrectly placed at the end of
conversation_service_dependency(), after branches that already return or raise.
Consequently get_conversation_service() returned None and FastAPI injected None
as the endpoint service. The first request then failed when the endpoint called
service.converse(request).

Surgical fix
- Moved ConversationService construction and return into
  get_conversation_service(), immediately after its dependencies are built.
- Removed the unreachable construction block from
  conversation_service_dependency().
- Added a regression test proving that the cached production factory returns
  the constructed service.
- No planner, executor, provider, persistence, tool, prompt, or external-service
  architecture was redesigned.

Files changed by this fix
- app/api/conversation.py
  Returns the configured ConversationService from the cached factory.
- tests/test_conversation_api.py
  Adds test_conversation_service_factory_returns_constructed_service using
  synthetic fakes only; it makes no provider or external-service request.
- output.txt
  Overwritten with this report as requested.
