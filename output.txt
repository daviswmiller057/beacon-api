### New user flow

For `Schedule lighting paperwork tomorrow`:

1. Interpreter returns a validated `SCHEDULE_TASK` intent.
2. Planner produces ordered task-resolution/creation and scheduling actions.
3. Executor reuses one unambiguous existing task or creates it in Vikunja.
4. Existing `SchedulerService` chooses and manages the work block.
5. The response includes the intent, plan, and executed-action audit.

`Buy Liquid IV tomorrow` creates only a Vikunja task.

### Gemini configuration

```dotenv
BEACON_INTERPRETER=gemini
GEMINI_API_KEY=your-key
GEMINI_MODEL=gemini-3.5-flash
VIKUNJA_DEFAULT_PROJECT_ID=7
```

Optional:

```dotenv
GEMINI_API_BASE_URL=https://generativelanguage.googleapis.com/v1beta
```

Without Gemini configuration, Beacon uses the local rules interpreter.

### Known limitations

- Relative dates support today and tomorrow.
- Part-of-day windows support morning, afternoon, and evening.
- Gemini requests are synchronous without retries.
- Creating tasks requires a default Vikunja project.
- Intake creation is not yet protected by persistent cross-request idempotency.

Recommended next feature: add a persistent intake execution journal and idempotency keys before adding more channels or action types.
